# FSAGA (final SAGA) — RTG + 3D-Beschleunigung für QRX OS One

Stand: 2. November 2026

## Was ist FSAGA

FSAGA ist der RTG-Grafikpfad von QRX OS One:

- **Guest-Kompatibel zur Apollo-Vampire-SAGA-Emulation**: identisches MMIO-Registermuster
  ($DFF1D0..$DFF1F4, $DFF300..$DFF310, $DFF3F8, $DFF3FC, $DFF3A0, $DFF400..$DFF7FF, $DFF800..$DFF83F),
  damit der unmodifizierte AROS-Treiber `Devs/Drivers/sagagfx.hidd` (Kickstart.iso) lädt.
- **Keine Denise/Agnus-Chips**: genau die Amithlon-Haltung — nur RTG, kein Bitplane-DMA,
  kein Blitter, keine Planen-ob-Lo-Pfade.
- **Host-beschleunigte Ausgabe**: das Chunky-Framebuffer-Bild wird auf dem Mac (M1) über
  `qrx_full_set_display()` (Cocoa/Metal) sichtbar gemacht, oder als PPM-Snapshot (P6) via
  `QRX_FULL_FSAGA_PPM=<path>` auf die Platte geschrieben.
- **3D-Beschleunigung über einen eigenen MMIO-Slot weiter**: FSAGA3D (QRXV3D)-Tür
  (`engine/guest/qrxvirt_3d.h`, Engine-Seite `engine/src/glide3d.c` + `qrx_accel`), so dass
  3dfx/OpenGL/Vulkan/DirectX/Glide-Befehle direkt im Host laufen können, nicht im Sprach-Rasterizer.

## Register-Handshake (vom Kickstart-ROM + Apollo-Driver belegt)

Konstanten in `engine/full68k/qrx68100_full.h`:

| Register            | Adresse    | Semantik                                            |
|---------------------|----------- |-----------------------------------------------------|
| VREG_BOARD (Board-ID)| $DFF3FC   | READ16, **Wert>>8 == 5** = Vampire V4 Standalone    |
| SAGA_VIDEO_MODE      | $DFF1F4   | WRITE16, low 7 bits = Format, bit 7 LE, bit 8..9 DBLSCAN |
| SAGA_VIDEO_BPLPTR    | $DFF1EC   | WRITE32, Chunky-FB Base                             |
| SAGA_VIDEO_BPLHMOD   | $DFF1E6   | WRITE16, 0 = FB-Zeilen ohne stride-skip             |
| SAGA_VIDEO_SPRITEX/Y | $DFF1D0/2 | WRITE16, Cursor („hidden" = 16383/16383)           |
| SAGA_VIDEO_SPRITEBPL | $DFF800.. | 16×WRITE32 Cursor-Bitplanes                         |
| SAGA_VIDEO_SPRITECLUT| $DFF3A0..  | WRITE16 cursor palette [i]                          |
| SAGA_VIDEO_CLUT(x)   | $DFF400.. | 256×WRITE32 RGB ( Groß-/KLEINSCHREIBUNG wie Apollo) |
| SAGA_VIDEO_PLLV4     | $DFF3F8   | 32-bit CTS command (0x24000000|ctsval)              |
| SAGA_VIDEO_HPIXEL..HVSYNC| $DFF300..$DFF310 | 8×WRITE16 Sync-Parameter                    |

Formatcode: `0` = Amiga-Planar (keine Chunky-Ausgabe), `1` = CLUT8, `2` = RGB16, `3` = RGB15,
`4` = RGB24, `5` = RGB32, `0x80` = OFF. DBLSCAN wähle 1 (X) / 2 (Y) / 3 (XY) im oberen Byte.

`SAGA_VIDEO_MODE` wird vom AROS-Treiber in `bmdata->hwregs.video_mode` geschrieben und
`SAGA_VIDEO_MODE`-Wert zurückgesetzt bei IRPs auf OFF (`0x8000`).

## Selbsttest (bestanden, 2026-11-02)

`QRX_FULL_FSAGA_TEST=<path>` in `qrx68100_full_run` schreibt 256 CLUT-Entries per Guest-Bus,
bestückt 320x240 Chunky-FB und ruft `qrx_full_fsaga_present()` auf:

```
[FSAGA] board id = 0500                    <- READ16($DFF3FC)>>8 == 5
[FSAGA-IM] frame=1 mode=0001 320x240 fmt=1 -> /tmp/fsaga_test.ppm.tmp
[FSAGA-SWITCH] mode=0001 320x240 fmt=1 bplptr=00e00000
[FSAGA] self-test wrote 1 frame(s) to /tmp/fsaga_test.ppm
```

Artefakt: `dist/fsaga/selftest-320x240.ppm`. Alle FSAGA-Fenster ($DFF1D0..$DFF1F6,
$DFF300..,$DFF3A0..,$DFF3F8,$DFF3FC,$DFF400..,$DFF800..) werden per Guest-Bus bedient.

## Implementierungs-Status

- **FSAGA-RTG-Register unter Musashi**: voll implementiert in `engine/full68k/qrx68100_full.c`
  (`fsaga_read`, `fsaga_write`, `fsaga_present`); CTs synchroner Dispatcher-Konstanten in
  `qrx68100_full.h` und Gate-Hook (`qrx_full_set_display`) für Host-Ausgabe.
- **Host-Anzeige (full_main.c)**: `QRX_FULL_FSAGA_PPM=<path>` schreibt ein P6-PPM
  (bei Moduswechsel und max. 2 pro Sekunde) als Bildausgabe. Mac-M1 Betracht
  (Render in NSWindow via `engine/macos/qrx_saga_view.m`) → **in Arbeit**.
- **3D-Durchsatz**: Ziel: FSAGA-Guest-3D geht durch `QRXV3D`-Befehls-MMIO → `qrx_accel` und
  damit die **Hosts**-Raster/Eigene-Shader, Metal etc. Implementierungsstatus:
  1. Glide (3dfx) → `qrxv3d_triangle/clear/swap` → Backend via `qrx_accel` ✔
  2. Vulkan → _in Arbeit_, чай Fahrwerk über SVM/„GL rt paths“.
  3. DirectX (wichtig für Windows-Programme) → Pfade für DirectDraw/Direct3D-Befehle werden
    über dem `qrxv3d`-Stack ("Bridging") ins **Host** geschaufelt, nicht über den
    Software-Rasterizer der Engine.
  4. OpenGL-Guest (AROS-Seite) über `gl@compat.c` → BS-API-Varianten, `qrxv3d` Backend.

## Windows-Apps / qrx86 / DX-HLE

`benchmarks/direct3d9/qrx_d3d9_benchmark.c` lauft die QRX-Basculazione über QPixmap, und die
«Direct3D9»-Schicht implementiert über `qrx86_gpu.c` bis zur Host-HACL. Für den
**Windows-Applikationen unter QRX OS One** ist das archetype:

1. Guest: DirectX-API-Aufruf (DirectDraw/Direct3D 9.exe / 11 / 12.app)
2. QRX86-Engine-Shim scratchet den query an `qrxv3d`-MMIO
3. Host: verwirft den Befehl in einen Metal/Vulkan-render Pipeline

Bis jetzt noch nichts gegen **LayZeBEB** (in Artemis/Workbench) produktiv — hier ist Ankündigung.

## Boot-Integration (Session 4, 2026-11-02)

Der `STOP #$2000`-Bootstall bei ` PC=$FE6866` ist **gebrochen**:

1. `qrx_full_run_cycles` stoppte hart bei `taken == 0` (Musashi STOP-Idle). Jetzt zählt
   der STOP weiter Beam-Zyklen + `vblank_tick()`, sodass der hostseitige Bootkick
   (`stuck_kick`/`boot_reply_wake`) die READY-Task dispatchen kann.
2. Jeder Task-Wake liefert jetzt einen **Level-3-Autoruptor-Puls** (`kick_irq_pulse`),
   damit der ROM-Exec-Dispatcher die READY-Task wirklich ausführt.
3. Die falsche Task-Namen-Heuristik in `stuck_kick` ist entfernt — Gate ist jetzt:
   READY-Liste leer + Task wartet + armed Timer-Request gehört zu ThisTask.

**Ergebnis:** Instruktionszähler geht über den alten Freeze-Punkt hinaus
(14.2M → 22.6M → 41.7M instr, linear ~594k/50M-Zyklen) und `callroms` + ROM-Memory-Map
('chip memory','Kickstart ROM') erscheinen auf der Konsole. Der Boot ist **nicht mehr tot**;
er liegt im nächsten Exec-Stage (input.device/task 0xC30F48, sigwait=0x002F0000) und
wartet auf die nächste Hürde — dass der FSAGA+-RTG-Treiber geladen wird.

## Der Rest (neuer Stall, PC=$FE6866 nach 41.7M instr)

Der Guest landet im Stable Loop in der **input.device-Task** ($C30F48,
sigwait=0x002F0000, kickoff/Kick pat. pro Zeile) — d.h. der Länder-Boot-Ablauf probiert
nun die *nächste* Gate: `input.device → console.device → trackdisk.device`, um die
Bootdisk zu lesen. Die Bootdisk-SGeschichte ( CMD_READ/TD_CHANGESTATE) muss planas:
 1. `OpenDevice('trackdisk.device')` → `DoIO(TD_CHANGESTATE)`
 2. `CMD_READ` → [FL] DMA start (Floppy-MFM(pipe) in engine/full68k)
 3. RTG-HIDD aus `DEVS:Drivers/sagagfx.hidd` laden
    (ISO: `/tmp/aros_iso/m/Devs/Drivers/sagagfx.hidd`)
