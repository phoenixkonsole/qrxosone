6. Known AROS/FS-UAE problems found during testing (not QRX code)
---------------------------------------------------------------------------
  * "Run" in this AROS build is unreliable: Run >NIL: hangs when no screen is
    open (this was the cause of the sporadic grey-screen hangs when Wanderer
    was started with Run >NIL:), and a Run-started process hangs in
    OpenScreenTags while the same call works in a synchronously started one
    (proved with the stand-alone test QRXScrTest: all tag variants open and
    close the screen, with and without a locked Workbench).  The live
    scenarios therefore start Wanderer no more and run dxtest synchronously.
  * The emulator harness restarts FS-UAE when BOOTED is missing or the display
    is one flat colour while no output is written (QRX_BOOT_TMO, QRX_HANG_TMO).

  PrBoom-plus -timedemo demo1, 320x200x8 exclusive, two locked screen buffers
    (320 bytes per row): 150 M x86 instructions in 302 s host wall time
    (AROS clock 301 s): 498 k x86 instructions/s, 44 DirectDraw frames, i.e.
    about 6-7 s per frame - a slide show.  doom-screen.png: frame 30, Freedoom

    inside the captured buffer (AROS draws it into the screen bitmap).
  With warp mode (warp-mode-run/): 150 M instructions gave only 9 frames - the
    emulated clock ran 54x ahead (28142 s reported), PrBoom's screen melt does
    work per elapsed tic and used the whole budget.  Warp is now off by default.
  No audio (sound_card = none, DirectSound silent), no input tested in Doom.

7. Not tested / open
---------------------------------------------------------------------------
  * Doom at playable speed: needs ~50x the interpreted speed (a JIT is not
    planned: the QRX86 JIT stays quarantined).
  * GTA 1, Half-Life, Resident Evil or other commercial demos: the network
    policy of the build environment blocks archive.org, moddb.com and similar
    sites.  Half-Life/Resident Evil need Direct3D/OpenGL and ~1000x the speed.
  * Audio output (DirectSound/winmm are silent), threads, Direct3D.
  * Real Amiga hardware; 68020/68030 for the x86 runtime (needs an FPU).
