QRX OS One 22.5.11 - PowerPC (PPC32) architecture / ABI plan
==============================================================

Status: PLAN ONLY.  No PowerPC instruction is executed by any QRX 22.5.11
component.  amigacheck/qrx-binary-identify report PowerPC ELF files as
"NOT supported".  No compatibility with AmigaOS 4, MorphOS or Linux/PPC is
claimed.  No AmigaOS 4 Kickstart/ROM modules or libraries are bundled, and
none may be: they are proprietary (Hyperion/A-EON); only user-supplied,
legally owned copies could ever be referenced, and the plan below is designed
not to need them.

1. Why two separate runtimes
----------------------------
Linux/PPC32 and AmigaOS 4 share the CPU (PowerPC 32-bit, big-endian) and the
ELF container, and nothing else:

                       Linux/PPC32 (SysV PPC ABI)      AmigaOS 4.x
  binary               ELF32 ET_EXEC/ET_DYN, PT_INTERP  ELF32 ET_EXEC/ET_DYN (elf.library),
                       /lib/ld.so.1, glibc/musl         no PT_INTERP, .so via elf.library
  OS entry             `sc` with r0 = syscall number    interface calls through
                       (Linux syscall table)            struct Interface vtables
                                                        (IExec->..., r3 = self)
  libraries            libc.so via dynamic linker       exec.library interfaces,
                                                        newlib.library, clib4/clib2
  data model           ILP32, r1 stack; r2 = TLS        ILP32, r1 stack; small-data base
                       pointer, r13 = small data (SysV) register usage differs (to be
                                                        verified from public SDK docs)
  68k interop          none                             68k emulation layer (Petunia,
                                                        EmuTrap) for legacy libs
  graphics/GUI         X11/Wayland (not in scope)       Intuition/Reaction/graphics v54

Sharing an "OS layer" between them would couple two unrelated system ABIs.
The only legitimately shared part is the CPU core.

2. Component layout (to be implemented in later releases, each gated)
----------------------------------------------------------------------
  qrxppc-core      portable PPC32 user-mode interpreter (no FPU first),
                   big-endian guest memory map, exact CR/XER/LR/CTR semantics,
                   instruction counting watchdog identical to QRX86
                   (every guest instruction charged, resumable long ops,
                   trace cap), fail-closed on unknown opcodes.
                   Host-testable with reference vectors generated by
                   powerpc-linux-gnu-as + qemu-ppc on the build host.
  qrxppc-linux     Linux/PPC32 personality: ELF loader for static binaries
                   first, `sc` dispatcher mapping a small whitelist of
                   syscalls (exit, write, read, brk, mmap anon, openat, close,
                   fstat, clock_gettime) to AROS DOS calls, errno mapping,
                   auxv/stack layout per SysV PPC ABI.  Dynamic ld.so later.
  qrxppc-os4       AmigaOS 4 personality: research only until an
                   independent, clean-room description of the needed
                   interfaces exists.  Would need: elf.library-style loader,
                   Interface objects (IExec/IDOS/IGraphics/IIntuition) whose
                   methods are trampolines into native AROS m68k calls,
                   newlib/clib4 handled as guest code where licences allow.
                   No OS4 binaries, ROM files or SDK headers are shipped.

  Dispatch: amigacheck/qrx-binary-identify already distinguish PPC ELF.  A
  future launcher may route: PT_INTERP "/lib/ld.so.1" or Linux OSABI ->
  qrxppc-linux; OS4 markers (.amigaos section names, absence of PT_INTERP,
  links to elf.library/newlib.library) -> qrxppc-os4 (refused while research
  only); MorphOS (ET_REL PPC, .morphos section) -> refused.

3. Performance reality check (m68k host)
----------------------------------------
Interpreting PPC32 on a 25-60 MHz 68030/68040/68060 yields well below 1 guest
MIPS.  Useful for small CLI tools, not for GUI applications.  A PPC JIT is out
of scope until qrx-jit-selftest EXECUTE passes on 68040/68060 and the QRX86
JIT quarantine has been lifted by the procedure in JIT-SELFTEST-22.5.11.txt.

4. Acceptance gates for the first PPC release
---------------------------------------------
  * Host: instruction tests vs qemu-ppc reference traces; watchdog/trace
    tests like tests-22.5.11/test-qrx86-interpreter.sh.
  * Target (FS-UAE 68040 + real AROS): a static PPC32 Linux "hello" built
    with powerpc-linux-gnu-gcc -static runs and returns its exit code.
  * Documentation states clearly: "Linux/PPC32 static CLI subset", nothing more.
